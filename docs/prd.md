## 1. 问题陈述（可观察事实）

1. **同主题多版本共存**：教务处教学通知按学年/年度重新发布，同一事项（转专业、缓考、重修、学籍异动、毕业论文）在列表中同时存在 2024、2025、2026 年多个版本，标题高度相似。
2. **页面是纯 HTML 列表，无结构化字段**：列表页 `jwb/jxtz.htm` 每条只有「标题 + 发布日期 + 详情链接」，详情页是富文本正文 + 附件（doc/pdf/xls），**没有公开 RSS、没有 JSON API**。
3. **关键约束藏在正文里**：报名截止日期、适用年级、生效学期、办理地点都以自然语言出现在正文段落或附件表格中，无法直接用字段过滤。
4. **由此产生的失效模式**：学生检索"转专业报名截止日期"，语义检索会同时命中 2024/2025/2026 三个版本，且因为旧版本正文更长、关键词更密，反而更容易排在前面——用户把**已失效的旧规则当现行规则**。这是本项目的核心技术挑战：**时效性幻觉（temporal hallucination）**，而不是通用 RAG 的"答案对不对"。

> 一句话：通用 RAG 的失败是"答错"，本项目的失败是"答对了一个已经不存在的规则"。

## 2. 目标用户

**主要 persona：需要快速确认"现行有效版本"的学生（P1）**

| 属性 | 描述 |
|---|---|
| 典型查询 | "2026 年转专业报名截止日期"、"这学期缓考怎么申请"、"重修报名什么时候结束" |
| 关心什么 | **这条规则现在还算不算数**、截止日期是哪天、我这个年级适用不适用 |
| 不关心什么 | 通知全文、历史沿革、政策解读 |
| 失败代价 | 按过期通知准备材料 → 错过时间 → 无法补救 |
| 使用场景 | 手机/笔记本，考前或报名季，30 秒内要答案 |

**次要 persona：维护采集范围与评估集的学生开发者（P2）**

| 属性 | 描述 |
|---|---|
| 典型查询 | "这周新增了哪些通知"、"哪些题被判成过期误召回" |
| 关心什么 | 采集是否漏页、评估集是否覆盖跨年度陷阱 |
| 使用入口 | 采集脚本 CLI + `/api/v1/eval/summary` 看板 |

## 3. 成功指标

指标同时是 **E 的跑批口径**与 **F 的验收依据**；口径定义写在 `SKILL.md §5`，不得各自发明。

| # | 指标 | 基线 | 目标 | 测法 |
|---|---|---|---|---|
| M1 | **旧版本误召回率** `stale_recall_rate` | **62%**（无时间过滤，`time_filter.mode=off`，在 12 条跨年度陷阱题上测得） | **≤ 15%**（冲刺 ≤10%） | 陷阱题 top-3 引用中出现 `is_current=false` chunk 的题数 ÷ 陷阱题总数（分母 ≥10） |
| M2 | **Faithfulness** | — | **≥ 0.85** | RAGAS，答案每句须能被 citations 支撑 |
| M3 | **无答案拒答率** `refusal_rate` | — | **≥ 0.90** | `refused=true` 的无答案题数 ÷ 无答案题总数（分母 ≥10） |
| M4 | **问答接口 p99 延迟** | — | **< 2s**，流式首 token **< 1s** | 30 并发压测 5 分钟，`latency_ms` P99 |
| M5（辅助） | Context Precision | — | ≥ 0.70 | RAGAS，用于分离检索层故障 |

**关于 M1 的基线 62%**：第 3 周在 12 条陷阱题上用 `mode=off` 跑出的观测值（典型错例：`2024年转专业工作通知` 排第一、`2026年` 排第三）。该数字会随采集总量变化，**每次全量回归必须在报告中重述当次基线**，不得引用旧数字。

**降级规则**：若第 4 周 M1 只能做到 20%，则必须满足"top-3 中至少包含 1 条 `is_current=true` 的现行版本"（即可读，不误判），并在 PRD 修订记录中写明原因。

## 4. 范围（In / Out）

### In-scope

1. 采集**限定** `https://www.sgu.edu.cn/jwb/jxtz.htm` 的公开列表页及其详情页（附件只记录链接，不下载正文）。
2. 问答**覆盖**教务处教学通知这一栏目：报名、考试、学籍、培养方案、实践教学相关的通知正文。
3. 时间感知检索：时间意图识别 → 按 `publish_date` / `effective_period` 硬过滤 → 语义召回 → 重排。
4. 答案**必须带引用**（可点击跳回原始通知），无依据时**必须拒答**。
5. 一个面向 P2 的评估看板（指标 + 逐题明细 + 回归趋势）。
6. `docker compose up` 一键启动全栈。

### Out-of-scope（明确不做）

1. **不覆盖全校所有二级栏目**（不抓 `www.sgu.edu.cn` 的其它部门网站，不抓研究生院、图书馆）。
2. **不处理登录后内容**：不模拟登录、不使用 cookie 会话语义抓取任何需授权的页面。
3. **不做多轮对话记忆**：`session_id` 字段预留，v1 每轮独立检索（不实现指代消解）。
4. **不做移动端原生 App**，只做响应式 Web。
5. **不做全文翻译、摘要生成、通知推送、订阅提醒**。
6. **不做 OCR**：纯图片附件不进入索引，在列表中标记为"暂不支持"。

## 5. 约束

### 5.1 工程约束（合规优先，不可协商）

| 约束 | 取值 | 实现位置 |
|---|---|---|
| 只抓公开页面 | 无认证、无 cookie、遵守 robots | `ingestion/ingestion/config.py` |
| 域名白名单 | `ALLOWED_DOMAINS=sgu.edu.cn`（含子域） | 抓取器前置校验，越界直接抛错 |
| 单域限速 | `REQUEST_DELAY_SECONDS=1.0`（**下限 1**），单并发 | 抓取器 sleep + 串行队列 |
| 单次页数上限 | `MAX_PAGES_PER_RUN=50`（只算**列表页**） | 分页循环硬上限 |
| 单次请求上限 | `MAX_REQUESTS_PER_RUN=800`（含详情页与重试，硬顶 2000） | `Fetcher._guard()` |
| 不递归整站 | 只走"列表页 → 详情页"两跳；附件只记链接不下载 | 无泛洪爬虫 |
| 不假设 API/RSS | 采集层只实现 HTML 解析 | 无"接口抓取"分支 |
| 遇 WAF 不绕过 | 403 时 `crawl` 以 exit 4 结束并给出指引；**禁止**提高并发/缩短延时/轮换 UA | `fetcher.BlockedError` + `cli._print_blocked()` |

### 5.2 选型约束

1. **Go API 与 Python RAG 通过内部 HTTP 解耦**：C 不得直接连 Qdrant、不得自己算 embedding；B 不得暴露 `/api/v1/*`。
2. **前端不直接调用 RAG 核心**：D 只认 `VITE_API_BASE_URL → /api/v1/*`，跨域由 Nginx 收敛。
3. **替换任一层必须附理由 + 基准数据 + 受影响成员**（`references/tech-baseline.md`）。
4. **契约先于实现**：第 1 周冻结 `docs/api.md` 与 `references/api-contract.md`，之后只允许加可选字段。

### 5.3 团队约束

- 6 人，每人一条链路，**任何一人工作量 ≤ 总量 25%**（即 ≤ 1.5 人份中的 1 份，实际按 16.7%±3% 控制）。
- 每条链路的接口在第 1 周固化在 Skill 中，禁止开发期单方面修改。

## 6. 交付物与验收（第 4 周）

| 成员 | 链路 | 可验收产出 | 验收方式 |
|---|---|---|---|
| A | 采集与 ETL | 定时运行脚本 + `chunks.jsonl`（含 `publish_date`/`effective_period`/`doc_version`/`content_type`） | 跑一次 → 行数、字段完整率 100%、越界域名访问 0 次 |
| B | 检索与 RAG 核心 | `POST /internal/retrieve` 可用，含时间过滤与 Rerank | 用 E 的 20 条 query 抽查 top-8 合理性 |
| C | Go API | 全部路由注册 + SSE 可连通 + JWT/限流 | `curl` 五个端点 + SSE 收到 `done` 事件 |
| D | Vue 3 前端 | 虚拟滚动列表 + SSE 问答 + ECharts 看板，Mock 可跑 | `VITE_USE_MOCK=true` 独立演示 |
| E | 评估体系 | 40 条 query（≥10 无答案、≥10 跨年度陷阱）+ 基线指标表 | `eval/` 一条命令产出报告 |
| F | 基础设施 | `docker compose up` 一键启动 + CI 三绿 | 干净机器 10 分钟内可访问 |

**整体验收（放行条件）**：M1 ≤15%、M2 ≥0.85、M3 ≥0.90、M4 <2s，且 `docker compose up` 后 README 的最小可跑示例可原样执行成功。

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 官网改版/反爬 | 采集中断 | 解析层留 fixture 快照；失败不阻塞其他链路（读已入库数据） |
| `effective_period` 提取准确率低 | M1 不达标 | 提取不了就显式 `unknown`，靠 `publish_date` 兜底；不猜 |
| bge-m3 本地推理慢 | 首 token >1s | 开发期用小模型 mock，最终环境用 GPU 或预计算向量 |
| 契约被单方面修改 | 集成崩 | `check-contract.sh` 进 CI；契约变更需 C+D 双确认 |
| 六人并行但互相等待 | W2 延期 | 全员 Mock-first：B 用假 chunk、D 用 Mock、C 用假 RAG 响应 |
